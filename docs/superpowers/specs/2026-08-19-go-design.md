# Go — Optimization Design

Date: 2026-08-19
Repo-relative path: `docs/superpowers/specs/2026-08-19-go-design.md`

## Goal

Optimize the Go rules engine and the built-in Greedy AI. Priorities (user-ranked):
**Performance → Readability → Correctness → Polish.** Start with the hottest
measured bottleneck: the Greedy AI's candidate evaluation.

## Current state

- `gameboard.py` — BFS-based group/liberties computation, correct and
  `pygame`-free/headless-testable. 26 unit tests pass.
- `ai.py` — `GreedyAI._score_move` simulates each candidate on a full board
  copy and calls `score_areas()` twice per candidate.

### Measured bottleneck

Profile of `GreedyAI().choose()` on an empty board:

- `score_areas()`: **0.31s of 0.32s total (~96%)**, called **722 ×**
  (361 candidate points × 2: before + after).
- Each `_score_move` also makes a full-board copy (`[row[:] for row in grid]`)
  per candidate.

So the AI eliminates a 19×19 flood fill ×2 for every board point, most of which
are irrelevant.

## Optimization plan

### B — Performance

1. **Candidate pruning.** Restrict legal candidates to empty points adjacent to
   an existing stone. This removes irrelevant interior/empty regions from
   consideration on both almost-empty boards and mid/late games. Provides the
   candidate-count reduction without changing which moves are *considered*.

2. **Delta scoring instead of full-board `score_areas()` per candidate.**
   For a candidate move, compute only the *local* change it causes:
   - number of opponent stones captured by this move, and
   - the point gained by the placer.
   Return `(delta_gain) + captured_bonus * captures`, where
   `captured_bonus` is an explicit named weight (default 1.0) that preserves
   the current greedy weighting (captures were already implicitly rewarded by
   area scoring; this keeps the *intent* explicit and behavior-compatible).

   This avoids the two full-board flood fills per candidate.

3. **Avoid per-attempt full board copy.** Copy the grid once for the scoring
   loop, simulate a candidate, then revert the copied grid — not a fresh
   `[row[:] for row in grid]` per candidate.

### C — Readability

4. **Unify duplicate capture logic.** `GameBoard.resulting_key` and
   `GameBoard.make_move` each implement the same "remove opponent groups with no
   liberties" loop. Extract a single private helper (e.g.
   `_capture_opponent(x, y, color) -> list[coords]`) used by both, removing the
   duplication.

5. **Clarify AI scoring.** Name the scoring weight, and structure `_score_move`
   to reflect: `delta = local gain + capture bonus`. Add short docstrings.

### A — Correctness

6. **Delta scoring equivalence.** Add a test asserting the delta-based scoring
   equals a full-reference `score_areas()`-style evaluation on a set of board
   configurations (mid-game + capture-heavy), so the optimization provably does
   not change the AI's choices.

7. **Candidate-pruning correctness.** Test that pruning never drops a legal
   capturing move (i.e., every legal point with any relevant effect is still
   considered), and that when all pruned points are skipped the AI still returns
   a legal move or passes.

### D — Polish (low-cost only)

8. If trivially available while editing `ai.py`, no behavioral adds — keep the
   scope tight.

## Architecture

- `GameBoard` remains the single source of truth for rules; gains one extracted
  capture helper and reuses it in both call sites.
- `ai.py` `GreedyAI` gains:
  - `_candidates()` — pruned legal points
  - `_delta_score(...)` — local scoring
  - a shared scratch convention (one copied grid reused per `choose` call)

## Data / control flow

`choose()` -> `_candidates()` (pruned) -> for each, simulate on shared scratch
board -> `_delta_score()` -> pick argmax. The fold only mutates `_scratch`.

## Error handling

- Pruned-candidates may be empty (no stones yet): fall back to a trivial legal
  point (e.g. center) or pass `None` — must produce a legal move or `None`
  identically to the original.
- Revert-after-simulate must reset the scratch grid exactly; tests assert the
  scratch equals the original post-loop.

## Testing & verification

- Baseline: run `python -m unittest test_gameboard test_game test_ai test_player
  test_sgf` (currently 26 pass).
- After: all existing tests + new delta-equivalence and pruning tests.
